Dùng để tìm đúng file khi đọc code. Không cần học thuộc tất cả trong buổi đầu.

Website khởi động thế nào?

  1. index.html chứa <div id="root"> và nạp src/main.tsx.
  2. main.tsx dùng createRoot(...).render(...) để React dựng App vào vùng root. Ở chế độ phát triển, URL ?prototype=members chọn prototype riêng.
  3. App.tsx đọc trạng thái đã lưu. Chưa chọn Gia đình → OnboardingModal; đã có Gia đình nhưng chưa chọn Thành viên → MemberSelection. Nếu có Thành viên đã nhớ, App xác minh với repository trước khi vào màn chính; có giao diện đang tải và thử lại khi lỗi.
  4. Khi đã chọn Thành viên, App ghép AppHeader, PlanView hoặc MenuView, BottomNav và ShareHouseholdModal. Tab ban đầu là Kế hoạch.

Nguồn hành vi: index.html, src/main.tsx, src/App.tsx. Cơ chế React: Render and Commit.

Giao diện và dữ liệu nối với nhau thế nào?

Đổi tab

Bấm Menu → BottomNav gọi hàm App truyền xuống → App đổi activeTab → React chọn MenuView.

Thao tác đổi tab không cần ghi một bản ghi vào database. MenuView xuất hiện rồi tải dữ liệu riêng.

Thêm Món ăn

Trong MenuView, lưu biểu mẫu → handleSaveDish gọi repository.addDish → sau khi lưu thành công, loadDishes đọc lại danh sách → setDishes(data) → React cập nhật giao diện.

Ví dụ riêng của dự án, xem src/components/MenuView.tsx:113 và :57.

Dữ liệu được lưu ở đâu?

src/services/repositoryFactory.ts chọn repository theo cấu hình Supabase. Với Menu và Kế hoạch: có client Supabase thì dùng repository Supabase; thiếu cấu hình thì dùng localStorage của trình duyệt. Đây là chọn theo cấu hình, không tự chuyển sang localStorage khi cloud đang lỗi.

Thành viên là trường hợp riêng: cần database. Không có client Supabase thì factory trả UnavailableMemberRepository, báo lỗi thay vì tạo danh sách Thành viên cục bộ. Vì vậy không nên suy ra toàn bộ website luôn dùng được khi chưa cấu hình cloud.

Trong chế độ Supabase, repository nhận thông báo thay đổi theo Mã nhà; ví dụ MenuView đăng ký theo dõi rồi tải lại danh sách. Việc này giúp các thiết bị trong cùng Gia đình thấy dữ liệu mới khi kết nối hoạt động.

Nguồn: repositoryFactory.ts, memberRepository.ts, supabaseDishRepository.ts, MenuView.tsx; ADR-0005 và ngoại lệ trong ADR-0006. Cách dùng effect: Synchronizing with Effects.

Những từ sẽ gặp trong code

React
Thư viện JavaScript để xây giao diện từ component. Dự án khai báo phiên bản ^18.3.1.
Component
Một phần giao diện; ví dụ BottomNav. Function component trả về mô tả giao diện.
JSX
Cú pháp mô tả giao diện trong JavaScript, ví dụ <BottomNav />.
Props
Đầu vào component nhận từ cha. Có thể là dữ liệu hoặc hàm; ví dụ activeTab và onTabChange.
State
Thông tin React nhớ cho component. Hàm setter yêu cầu cập nhật; ví dụ setActiveTab('menu').
Render
React gọi component để tính giao diện. Sau đó bước commit cập nhật DOM cần thay đổi; không đồng nghĩa tải lại trang.
Repository
Trong dự án: phần cung cấp thao tác đọc/ghi dữ liệu, ví dụ getDishes và addDish.
Vite
Công cụ chạy môi trường phát triển và build dự án. React là phần thư viện giao diện được dùng trong dự án đó.

Nguồn chính thức: Component và JSX · Props · State · Render · Vite. Repository và phiên bản lấy từ mã nguồn dự án.

Bốn dòng để nhớ luồng Menu

// App: nhớ tab
const [activeTab, setActiveTab] = useState<NavigationTab>('plan');
// App: truyền giá trị và hàm xuống con
<BottomNav activeTab={activeTab} onTabChange={setActiveTab} />
// BottomNav: nút Menu gọi hàm khi được bấm
onClick={() => onTabChange('menu')}
// App: chọn giao diện (đã lược props)
{activeTab === 'plan' ? <PlanView /> : <MenuView />}
